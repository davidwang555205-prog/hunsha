# 内容主题改为内容引擎 JSON 配置

## 当前结论

主题不再由前后端写死，也不再使用“只能从内置主题中选择”的白名单。

`content_engines.config.seeding` 是用户在工作台看到的内容主题及内容素材的单一事实源：

- `bridalTopics`：婚纱 / 礼服主题列表。
- `dressTopics`：裙装 / 女装主题列表。
- 数组顺序就是工作台主题下拉的展示顺序。
- 修改数组可新增、改名、删除主题；后台保存时只校验数组非空、主题名无首尾空格且不重复。

主题不配置专属素材时，内容引擎会用对应品类的默认变体银行和通用配图模板继续生成；因此新增主题不会阻塞生成。

## 修改主题和内容的方式

下面示例新增两个婚纱主题：

```json
{
  "bridalTopics": ["主推轻婚礼", "森系外景试纱"],
  "topicCopyKits": {
    "主推轻婚礼": {
      "titles": ["轻婚礼主纱怎么选"],
      "openings": ["预算有限也想把仪式感留住"],
      "observations": ["轻盈裙摆和利落腰线更适合户外走动"],
      "scenes": ["草坪婚礼"],
      "closings": ["先试走几步，再决定是不是你的主纱"],
      "tags": ["#轻婚礼", "#婚纱试穿"],
      "note": "面向偏好自然仪式感的新娘。"
    }
  },
  "bridalMainSceneByTopic": {
    "主推轻婚礼": "草坪婚礼",
    "森系外景试纱": "花园露台"
  }
}
```

主题改名时，要同时更新 `bridalTopics` / `dressTopics` 数组及所有以旧主题名为 key 的素材 map，例如 `topicCopyKits`、`xiaohongshuTopicOverrides`、`*MainSceneByTopic`、`englishVisualAlignmentByTopic`。旧 map key 即使因深度合并仍保留，也不会在工作台展示或被生成流程选中。

## 与生图提示词 JSON 的关系

`config.seeding` 负责主题、文案和配图计划，产出图片类型、场景、关键词档案等结构化参数。

`config.imagePrompt` 负责把这些参数转换成最终英文 prompt，包括场景、模特、光线、关键词档案和负面约束。它不维护主题名称，也不决定工作台主题列表。

主题相关的场景名、图片类型和关键词档案必须能在生图提示词 JSON 中找到对应定义，否则会使用后端的安全默认值。
